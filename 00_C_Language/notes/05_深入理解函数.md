# 1. return 语句

## 1.1 核心作用与基本用法

- **有返回值的函数**：`return` 语句的核心作用是提供函数的返回值，同时结束当前函数的执行，返回到函数被调用的位置。
- **无返回值的函数（`void` 类型）**：也可以使用 `return;`，通常用于检测到错误或前置条件不满足时，提前终止函数执行并返回。
```c
void print_logarithm(double x) {
    if (x <= 0.0) {
        printf("Positive numbers only, please.\n");
        return; // 提前结束函数，不执行后续代码
    }
    printf("The log of x is %f", log(x));
}
```

注：使用 `log()` 需要引入 `<math.h>` 头文件；浮点数比较建议写成 `0.0` 以匹配类型。

## 1.2 返回布尔值的函数（谓词 Predicate）

- **谓词（Predicate）**：返回布尔性质结果的函数，通常用于充当控制表达式，函数名常带有 `is`、`check` 等判断性前缀。
- **简化写法**：无需写冗长的 `if-else` 分支，直接返回关系/逻辑表达式的值（结果为 0 或非 0）。
```c
// 繁琐写法
int is_even(int x) {
    if (x % 2 == 0) return 1;
    else return 0;
}

// 极简写法
int is_even(int x) {
    return !(x % 2);
}
```

## 1.3 返回值的底层逻辑（按值传递）

- **临时变量机制**：函数返回一个值，本质上相当于定义了一个和返回值类型相同的**临时变量**，并用 `return` 后面的表达式对其进行初始化。
- **局部变量释放**：函数退出时，函数内的局部变量（包括形参）的存储空间会被释放；调用方拿到的是提前计算好、保存在临时变量中的值。
- **返回值是右值**：函数的返回值不是左值（不代表可写入的存储位置），不能对其赋值。例如 `is_even(20) = 1;` 是非法代码。

## 1.4 常见错误与代码质量

### 1.4.1 Dead Code（死代码）

- **定义**：在任何执行条件下都不可能到达的代码路径。
- **示例**：逻辑运算符使用错误导致分支全覆盖，后续代码永远无法执行。
``` c
void foo(int x, int y) {
    if (x >= 0 || y >= 0) { ... return; }
    else if (x < 0 || y < 0) { ... return; }
    // 下面这行永远执行不到，属于 Dead Code
    printf("x has a different sign from y.\n"); 
}
```
- **结论**：存在 Dead Code 一定意味着逻辑错误或语义错误，需要排查分支条件的合理性。

### 1.4.2 遗漏 return 语句

- **问题**：函数声明了非 `void` 的返回类型，但部分执行路径没有 `return` 语句就直接退出函数。C语言标准规定这种情况的返回值是**未定义的**，通常会返回随机的不确定值。
- **示例**：实现绝对值函数时，遗漏了 `x=0` 的边界分支。
- **隐蔽性**：编译器仅做语法检查和基础语义检查，不校验程序逻辑的完整性。这类 Bug 排查难度高，甚至可能在测试中因巧合不暴露问题。

### 1.4.3 编译器的告警是好事

编译器的报错和告警能提前暴露大量问题，节省调试时间。对于“返回值路径缺失”这类问题，编译时添加 `-Wall` 选项可以触发编译器的警告提示。

## 1.5 补充知识点

- **单目运算符 vs 双目运算符**：正号 `+` 和负号 `-` 是单目运算符，优先级高，与逻辑非 `!` 同级；加号 `+` 和减号 `-` 是双目运算符，优先级更低。

## 1.6 习题解答

### 1.6.1 习题 1

**题目**：编写布尔函数 `int is_leap_year(int year)`，判断参数 `year` 是否为闰年。

- 判断规则：能被 4 整除但不能被 100 整除；或者能被 400 整除。
- **参考代码**： 
```c
int is_leap_year(int year) {
    return (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
}
```

### 1.6.2 习题 2

**题目**：编写函数 `double myround(double x)`，实现小数的四舍五入。

- 示例：`myround(-3.51)` 结果为 `-4.0`，`myround(4.49)` 结果为 `4.0`。可调用 `<math.h>` 中的 `ceil` 和 `floor` 函数。
- 思路：正数加 0.5 后向下取整；负数减 0.5 后向上取整。
- **参考代码**：
```c
#include <math.h>
double myround(double x) {
    if (x >= 0) {
        return floor(x + 0.5);
    } else {
        return ceil(x - 0.5);
    }
}
```

更简洁的三元表达式写法：`return x >= 0 ? floor(x + 0.5) : ceil(x - 0.5);`

# 2. 增量式开发与函数分层设计

## 2.1 什么是增量式开发（Incremental Development）？
面对复杂问题（例如：由两点坐标求圆的面积），不要试图一口气写完整个程序，而是采用**「编写一点，测试一点」**的迭代策略。

### 2.1.1 核心步骤
1. **分析并分解问题**：将大问题拆解为多个独立的小问题
   - 第一步：由两点坐标求距离（即半径）。公式：`distance = √((x2-x1)? + (y2-y1)?)`
   - 第二步：由半径求面积。公式：`area = π * radius?`
2. **搭建代码框架**：先写出完整的函数定义，用 `return 0.0;` 这类最简单的占位代码填充函数体。
3. **编写测试入口（main 函数）**：在 `main` 函数中调用待实现的函数，编译运行。编译通过即可建立初步的代码结构信心。
4. **逐步填充逻辑并验证**：
   - 每次只添加一小步逻辑（例如先计算 `dx` 和 `dy`）。
   - 使用 `printf` 打印中间结果进行验证，如同盖房子的「脚手架」。
   - 验证无误后，将调试用的 `printf` 注释掉或删除。
   - 继续下一步逻辑开发，直到函数功能完全实现。

### 2.1.2 增量式开发的优势
- **心态平稳**：始终保留一个已知正确的版本作为基准，不会因为大段代码报错而陷入全面排错的困境。
- **易于排错**：如果新增代码出错，可以100%确定问题就出在刚刚改动的几行，避免在大量代码中盲目排查。

## 2.2 调试利器：printf 脚手架
- 测试阶段，如果怀疑某一步计算存在问题，直接插入 `printf` 打印对应变量的值（如 `dx`、`dy`）。
- 调试完成后，建议把调试用的 `printf` 注释掉（`/* ... */`），而非直接删除，方便后续出现 Bug 时重新启用排查。
- 补充说明：虽然现代 IDE 提供了强大的图形化调试工具（如 GDB），但 `printf` 仍然是最直接、最通用的底层调试手段。

## 2.3 代码风格与权衡：单行写法 vs 临时变量写法
实现 `distance` 距离函数时，常见两种编码风格：

### 1. 一行流（极简写法）
```c
return sqrt((x2-x1)*(x2-x1) + (y2-y1)*(y2-y1));
```
- **缺点**：代码过长，无法插入 `printf` 分步调试；且 `(x2-x1)` 被重复计算两次，存在效率损耗。

### 2. 临时变量写法（推荐）
```c
double dx = x2 - x1;
double dy = y2 - y1;
double dsquared = dx * dx + dy * dy;
double result = sqrt(dsquared);
return result;
```
- **优点**：代码逻辑清晰，方便分步调试，同时避免了重复计算，执行效率更优。

## 2.4 函数的组合与复用（Reuse）
解决完小问题后，通过函数调用组合实现更大的问题：
- **直接组合调用**：`double result = area(distance(x1, y1, x2, y2));`
- **封装高层函数**：为了后续调用方便，将组合逻辑封装为新的高层函数：
  ```c
  double area_point(double x1, double y1, double x2, double y2) {
      return area(distance(x1, y1, x2, y2));
  }
  ```

### 2.4.1 绝对避免：重复代码（反面教材）
**错误做法**：将 `distance` 和 `area` 内部的公式代码直接复制粘贴到 `area_point` 函数中。
- **后果**：如果后续发现 `distance` 函数逻辑有误需要修改，必须同时修改 `distance` 和 `area_point` 两处代码。维护重复代码极易遗漏、出错。
- **核心原则**：**尽可能复用（Reuse）已有的代码，函数封装的核心目的就是复用。**

## 2.5 函数的分层设计（Stratify）
解决复杂问题的核心思路是「大问题拆成小问题，小问题拆成更小的问题」，体现在代码结构上就是函数的分层设计。

- **底层函数（Level 1）**：如 `distance` 和 `area`，解决最基础的原子小问题。
- **中层函数（Level 2）**：如 `area_point`，通过调用底层函数组合解决中等规模的问题。
- **顶层函数**：如 `main`，调用中层或底层函数，统领整个程序的执行流程。

```
         [ main ]  (最高层，统领全局)
            |
      [ area_point ]  (中层，组合底层函数)
       /          \
[ distance ]    [ area ]  (底层，解决基础小问题)
```

**分层设计的好处**：代码逻辑清晰，每个函数各司其职，极大提升了代码的可读性、可维护性和复用率。

# 3. 递归

## 3.1 递归的概念与Base Case（基础情况）

- **递归（Recursive）**：如果定义一个概念需要用到这个概念本身，称该定义是递归的。
- **数学例子：阶乘（Factorial）**
  - 递归定义：(n! = n \times (n-1)!)
  - 致命问题：如果只有递归定义，计算永远不会终止
  - **Base Case（基准情况/终止条件）**：必须定义明确的终止条件，例如 (0! = 1)
  - 计算过程示例：(3! = 3 \times 2!)，(2! = 2 \times 1!)，(1! = 1 \times 0! = 1)
- **递归函数**：直接或间接调用自身的函数。

## 3.2 递归函数的代码实现

编写递归函数时，**必须优先编写Base Case**。

```c
int factorial(int n)
{
    if (n == 0)
        return 1; // Base Case 终止条件
    else {
        int recurse = factorial(n - 1); // 递归调用
        int result = n * recurse;
        return result;
    }
}
```

## 3.3 递归的底层运行机制：调用栈（Stack）

- **存储空间分配**：每次调用函数时，系统都会为该函数的参数和局部变量分配独立的存储空间；函数执行返回时，这些空间被释放。
- **堆栈（Stack）**：这种「先进后出」的数据结构称为堆栈。函数调用层层深入时，存储空间从一端不断增长（入栈）；函数逐层返回时，空间依次缩减（出栈）。
- **栈帧（Stack Frame）**：每一次函数调用所占用的独立存储空间，称为一个栈帧。
- **factorial(3) 执行图解**：
  1. `main` 调用 `factorial(3)`，分配第一个栈帧。
  2. `factorial(3)` 调用 `factorial(2)`，在原有栈帧基础上再分配一个新的栈帧（尽管代码中只定义了一次参数 `n`，但运行时不同层级的调用各自拥有独立的 `n` 变量）。
  3. 调用到 `factorial(0)` 时触发 Base Case，返回 1；随后逐层返回并计算 (n \times recurse)，同时依次销毁栈帧，最终退出递归。

## 3.4 递归的正确性证明：Leap of Faith 与数学归纳法

- **Leap of Faith（信仰之跃）**：编写 `factorial(n)` 时，不需要深入 `factorial(n-1)` 的内部执行细节，而是**直接相信**它能正确返回 ((n-1)!) 的结果。基于这个信任，只要保证 (n \times (n-1)!) 等于 (n!)，那么整个递归函数就是正确的。
- **数学归纳法（Mathematical Induction）**：
  1. 证明 Base Case 正确（例如 (0! = 1) 成立）。
  2. 证明递推关系正确（如果 (n-1) 的情况成立，那么 (n) 的情况也成立）。
  满足以上两点，递归函数的正确性就可以被严格证明。
- **无穷递归（Infinite Recursion）**：如果漏掉 Base Case，函数会无限调用自身，直到耗尽操作系统的栈空间，最终导致程序崩溃（段错误 Segmentation fault）。

## 3.5 递归的等价性与普遍性

- **递归与循环等价**：用循环能实现的逻辑，用递归都能实现；反之亦然。在计算机底层指令集中，通常只有跳转（分支）和循环，递归是高级语言提供的一种便捷抽象。
- **递归是计算机科学的精髓思想**：不仅体现在算法中（例如汉诺塔问题），C语言的语法规则本身就是递归定义的（例如「表达式」和「语句」的语法定义）。编译器在解析源代码时，也大量使用了递归思想。

## 3.6 习题解答

### 习题 1：编写递归函数求最大公约数（GCD，欧几里得算法）

**算法规则**：

1. 如果 (a) 除以 (b) 能整除，则最大公约数是 (b)。
2. 否则，最大公约数等于 (b) 和 (a%b) 的最大公约数。

注：为了兼容所有整数，通常先对参数取绝对值。

**代码实现**：

```c
#include <stdio.h>
#include <stdlib.h> // 用于 abs()
int gcd(int a, int b) {
    // 处理负数情况：欧几里得算法针对正整数，取绝对值可扩展适用范围
    a = abs(a);
    b = abs(b);
    
    if (a % b == 0) {
        return b; // Base Case
    } else {
        return gcd(b, a % b); // 递归调用
    }
}

int main(void) {
    printf("GCD of 48 and 18 is: %d\n", gcd(48, 18)); // 输出 6
    return 0;
}
```

### 习题 2：编写递归函数求 Fibonacci 数列的第 (n) 项

**数列定义**：

- `fib(0) = 1`
- `fib(1) = 1`
- `fib(n) = fib(n-1) + fib(n-2)`

**代码实现**：

```c
int fib(int n) {
    if (n == 0 || n == 1) {
        return 1; // Base Case
    } else {
        return fib(n - 1) + fib(n - 2); // 递归调用
    }
}
```

> 
> 注：该递归写法逻辑直观，但由于存在大量重复计算，时间复杂度为指数级 (O(2^n))。实际应用中求解大项数的斐波那契数列，通常会改用循环或动态规划进行优化。
