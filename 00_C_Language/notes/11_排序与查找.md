# 1. 算法的概念

算法（Algorithm）是将一组输入转化成一组输出的一系列计算步骤，其中每个步骤必须在有限时间内完成。

## 1.1 算法的基本示例

*   **求最大公约数（Euclid算法）**：输入是两个正整数，输出是它们的最大公约数。计算步骤是取模、比较等操作，一定能在有限的步骤和时间内完成。
*   **排序算法**：输入是一组原始数据，输出是排序之后的数据。计算步骤包括比较、移动数据等操作。

## 1.2 算法的核心特征：解决“一类”问题

算法是用来解决**一类**计算问题的，注意是**一类问题**，而不是一个特定的问题。

例如，一个排序算法应该能对**任意**一组数据进行排序，而不仅仅是对 `int a[] = { 1, 3, 4, 2, 6, 5 }` 这样一组数据排序。如果只需要对这一组特定数据排序，完全可以写成硬编码（如下所示），但这**不是**算法，因为它没有通用性。

```c
void sort(void)
{
    a[0] = 1;
    a[1] = 2;
    a[2] = 3;
    a[3] = 4;
    a[4] = 5;
    a[5] = 6;
}
```

由于算法是用来解决一类问题的，它必须能够正确地解决这类问题中的任何一个实例，这个算法才是正确的。对于排序算法，任意输入一组数据，它必须都输出正确的排序结果。

## 1.3 算法的正确性

不正确的算法有两种可能：
1.  **死循环**：对于该问题的某些输入，该算法会无限计算下去，不会终止。
2.  **结果错误**：对于该问题的某些输入，该算法终止时输出的是错误的结果。

**不正确的算法也有意义？**
有时候不正确的算法也是有用的。如果对于某个问题寻求正确的算法很困难，而某个不正确的算法可以在有限时间内终止，并且能够把误差控制在一定的范围内，那么这样的算法也具有实际意义。例如，有时候求解精确解很困难，往往会选择给出次优解的近似算法。

## 1.4 本章学习目标

本章将介绍几种典型的排序和查找算法，并围绕这几种算法做**时间复杂度分析**。

学完本章之后如果想进一步学习，可以参考一些全面系统地介绍算法的书籍，例如《TAOCP》（《计算机程序设计艺术》）和《算法导论》。


# 2. 插入排序

插入排序算法类似于玩扑克时抓牌的过程，玩家每拿到一张牌都要插入到手中已有的牌里，使之从小到大排好序。

## 2.1 算法思想

我们打牌时的思考过程通常是这样的：现在抓到一张 7，把它和手里的牌从右到左依次比较，7 比 10 小，应该再往左插，7 比 5 大，好，就插这里。
为什么比较了 10 和 5 就可以确定 7 的位置？为什么不用再比较左边的 4 和 2 呢？
因为这里有一个重要的前提：**手里的牌已经是排好序的。** 现在我插了 7 之后，手里的牌仍然是排好序的，下次再抓到的牌还可以用这个方法插入。

编程对一个数组进行插入排序也是同样道理，但和插入扑克牌有一点不同，**不可能在两个相邻的存储单元之间再插入一个单元，因此要将插入点之后的数据依次往后移动一个单元。**

## 2.2 代码实现

```c
#include <stdio.h>

#define LEN 5
int a[LEN] = { 10, 5, 2, 4, 7 };

void insertion_sort(void)
{
    int i, j, key;
    
    // 外层循环：从第2个元素开始，逐个向前面的有序序列中插入
    for (j = 1; j < LEN; j++) {
        // 打印每次循环开始前的数组状态（用于观察）
        printf("%d, %d, %d, %d, %d\n", 
               a[0], a[1], a[2], a[3], a[4]);
               
        key = a[j]; // 保存当前要插入的元素
        i = j - 1;  // 从已排序序列的最后一个元素开始比较
        
        // 内层循环：将所有大于 key 的元素向后移动一个位置
        while (i >= 0 && a[i] > key) {
            a[i+1] = a[i];
            i--;
        }
        
        // 将 key 插入到正确的位置
        a[i+1] = key;
    }
    
    // 打印排序后的最终结果
    printf("%d, %d, %d, %d, %d\n", 
           a[0], a[1], a[2], a[3], a[4]);
}

int main(void)
{
    insertion_sort();
    return 0;
}
```

**运行过程解析**：
初始数组：`10, 5, 2, 4, 7`
*   `j=1`：拿着 `5` (key)，与 `10` 比较，`10>5`，`10` 后移。`5` 插入到 `10` 前面。结果：`5, 10, 2, 4, 7`
*   `j=2`：拿着 `2` (key)，依次与 `10`, `5` 比较，均大于 `2`，依次后移。`2` 插入首位。结果：`2, 5, 10, 4, 7`
*   `j=3`：拿着 `4` (key)，与 `10` 比较后移，与 `5` 比较后移，`2<4` 停止。`4` 插入 `5` 后面。结果：`2, 4, 5, 10, 7`
*   `j=4`：拿着 `7` (key)，与 `10` 比较后移，`5<7` 停止。`7` 插入 `5` 后面。结果：`2, 4, 5, 7, 10`

## 2.3 算法正确性证明（Loop Invariant）

如何严格证明这个算法是正确的？也就是说，只要反复执行该算法的 `for` 循环体，执行 `LEN-1` 次，就一定能将数组排好序，而不管数组的原始数据是什么。

可以借助**循环不变式（Loop Invariant）**和数学归纳法来理解循环结构的算法。假如某个判断条件满足以下三条准则，它就被称为 Loop Invariant：

1.  **初始化（Initialization）**：第一次执行循环体之前该判断条件为真。
2.  **保持（Maintenance）**：如果第 \(N-1\) 次循环之后（或者说第 \(N\) 次循环之前）该判断条件为真，那么就有办法证明第 \(N\) 次循环之后该判断条件仍为真。
3.  **终止（Termination）**：如果在所有循环结束后该判断条件为真，那么就有办法证明该算法正确地解决了问题。

**插入排序的 Loop Invariant：**
> 第 `j` 次循环之前，子序列 `a[0...j-1]` 是排好序的。

**验证三条准则：**
1.  **初始化**：第一次执行循环之前，`j=1`，子序列 `a[0...0]` 只有一个元素 `a[0]`，只有一个元素的序列显然是排好序的。
2.  **保持**：第 `j` 次循环之前，如果“子序列 `a[0...j-1]` 是排好序的”这个前提成立，现在要把 `key=a[j]` 插进去，按照该算法的步骤，把 `a[j-1]`、`a[j-2]` 等等比 `key` 大的元素都依次往后移一个，直到找到合适的位置给 `key` 插入，就能证明循环结束时子序列 `a[0...j]` 是排好序的。就像插扑克牌一样，“手中已有的牌是排好序的”这个前提很重要，如果没有这个前提，就不能证明再插一张牌之后也是排好序的。
3.  **终止**：当循环结束时，`j=LEN`，如果“子序列 `a[0...j-1]` 是排好序的”这个前提成立，那就是说 `a[0...LEN-1]` 是排好序的，也就是说整个数组 `a` 的 `LEN` 个元素都排好序了。

可见，有了这三条，就可以用数学归纳法证明这个循环是正确的。这和递归证明递归程序正确性的思想是一致的，这里的第一条就相当于递归的 Base Case，第二条就相当于递归的递推关系。这再次说明了**递归和循环是等价的**。


# 3. 算法的时间复杂度分析

解决同一个问题可以有很多种算法，比较评价算法好坏的一个重要标准就是**算法的时间复杂度**。现在我们来研究一下插入排序算法的执行时间。为了习惯，我们设输入长度 `LEN` 用 `n` 表示。假设循环中每条语句的执行时间分别是 `c1`、`c2`、`c3`、`c4`、`c5` 这五个常数。

```c
void insertion_sort(void)
{
    int i, j, key;
    // 外层循环执行 n-1 次
    for (j = 1; j < LEN; j++) {
        key = a[j];                  // c1
        i = j - 1;                   // c2
        // 内层 while 循环执行 m 次（m取决于具体数据）
        while (i >= 0 && a[i] > key) {
            a[i+1] = a[i];           // c3
            i--;                     // c4
        }
        a[i+1] = key;                // c5
    }
}
```

显然外层 `for` 循环的执行次数是 `n-1` 次。假设内层的 `while` 循环执行 `m` 次，则总的执行时间粗略估计是：
\((n-1) * (c_1 + c_2 + c_5 + m * (c_3 + c_4))\)

这里 `m` 不是个常数，它不取决于输入长度 `n`，而是取决于具体的输入数据。

## 3.1 最好、最坏与平均情况

*   **最好情况（Best Case）**：数组 `a` 的原始数据已经排好序了。`while` 循环一次也不执行，总执行时间是 \((c_1+c_2+c_5)*n - (c_1+c_2+c_5)\)。可以表示成 \(an+b\) 的形式，是 \(n\) 的**线性函数（Linear Function）**。
*   **最坏情况（Worst Case）**：数组的原始数据是逆序的（从大到小排好序）。内层 `while` 每次都要执行到底。
*   **平均情况（Average Case）**：如果原始数据是随机的，那么每次循环将已排序的子序列与新插入的元素 `key` 相比较，子序列中平均有一半的元素比 `key` 大。
*   **结论**：在**最坏情况和平均情况下**，总的执行时间都可以表示成 \(an^2+bn+c\) 的形式，是 \(n\) 的**二次函数（Quadratic Function）**。

## 3.2 为什么更关心最坏情况？

在分析算法的时间复杂度时，我们更关心最坏情况，理由如下：
1.  **提供上界**：最坏情况给出了算法执行时间的**上界（Upper Bound）**。我们可以确信，无论给什么输入，算法的执行时间都不会超过这个上界，这为比较和分析提供了便利。
2.  **最坏情况频发**：对于某些算法，最坏情况是最常发生的情况。例如在数据库中查找某个信息的算法，最坏情况就是数据库中根本不存在该信息（找遍了也没有）。
3.  **接近平均情况**：虽然最坏情况是一种悲观估计，但很多问题的平均情况和最坏情况的时间复杂度差不多（如插入排序都是 \(n\) 的二次函数）。

## 3.3 渐进符号（\(\Theta\)-notation）

比较两个多项式 \(a_1n+b_1\) 和 \(a_2n^2+b_2n+c_2\) 的值（\(n\) 取正整数）可以得出结论：**\(n\) 的最高次幂是最主要的决定因素**，常数项、低次幂项和系数都是次要的。当 \(n\) 足够大时，二次函数显然远大于线性函数。

因此，我们可以用一种**更粗略的方式**来表示算法的时间复杂度：把系数和低次项都省去。在算法分析中，通常使用 \(\Theta(g(n))\) 来表示与 \(g(n)\) 同一量级的一类函数。

**\(\Theta\) 的数学定义**：
如果可以找到两个正的常数 \(c_1\) 和 \(c_2\)，使得 \(n\) 足够大的时候（也就是 \(n \ge n_0\) 的时候），\(f(n)\) 总是夹在 \(c_1g(n)\) 和 \(c_2g(n)\) 之间，就说 \(f(n)\) 和 \(g(n)\) 是同一量级的，\(f(n)\) 就可以用 \(\Theta(g(n))\) 来表示。

**证明示例**：
以二次函数为例，比如 \(1/2n^2-3n\)，要证明它属于 \(\Theta(n^2)\) 集合。
不等式两边除以 \(n^2\)，得到 \(c_1 \le 1/2 - 3/n \le c_2\)。
当 \(n\) 取 \(7\) 时，\(1/2 - 3/7 = 1/14\)。我们可以取 \(c_1 = 1/14\)，\(c_2 = 1/2\)，\(n_0 = 7\)。这样当 \(n \ge n_0\) 时，不等式总是成立的。

> ? **结论**：当 \(n\) 足够大时，任何 \(an^2+bn+c\) 都夹在 \(c_1n^2\) 和 \(c_2n^2\) 之间，相对于 \(n^2\) 来说 \(bn+c\) 的影响可以忽略，\(a\) 可以通过选取合适的 \(c_1, c_2\) 来补偿。

## 3.4 常见的时间复杂度量级

几种常见的时间复杂度函数按数量级从小到大的顺序依次是：
\(\Theta(1) < \Theta(\log n) < \Theta(\sqrt{n}) < \Theta(n) < \Theta(n\log n) < \Theta(n^2) < \Theta(n^3) < \Theta(2^n) < \Theta(n!)\)

*   **关于对数底数**：\(\log n\) 通常表示以 10 为底的对数。但是在 \(\Theta\)-notation 下，\(\Theta(\log n)\) 和 \(\Theta(\log_2 n)\) 没有区别（因为底数不同只差一个常数倍，常数在 \(\Theta\) 中可忽略）。在算法分析中，\(\log n\) 通常表示以 2 为底的对数。
*   **对数怎么出现的？**：插入排序的时间复杂度里只有加法和乘法，没有对数。但下一节的**归并排序**时间复杂度里就有 \(\log n\)（因为归并排序是将数组不断二分）。

## 3.5 Big-O notation（大 O 记号）

除了 \(\Theta\)-notation 之外，表示算法的时间复杂度常用的还有一种 **Big-O notation**。
*   \(\Theta\) 的含义类似于“**等于**”。
*   大 \(O\) 的含义类似于“**小于等于**”。

我们知道插入排序在最坏和平均情况下时间复杂度是 \(\Theta(n^2)\)，在最好情况下是 \(\Theta(n)\)。由于数量级比 \(n^2\) 小，所以总体上说插入排序的时间复杂度是 **\(O(n^2)\)**。

> **注**：受内存管理机制的影响，指令的执行时间不一定是常数，但执行时间的上界（Upper Bound）肯定是常数，这里假设语句的执行时间是常数只是一个粗略估计。


# 4. 归并排序

插入排序算法采取增量式（Incremental）的策略解决问题，每次添一个元素到已排序的子序列中，逐渐将整个数组排序完毕，它的时间复杂度是 \(O(n^2)\)。

下面介绍另一种典型的排序算法——**归并排序**，它采取**分而治之（Divide-and-Conquer）**的策略，时间复杂度是 \(\Theta(n\log n)\)。

## 4.1 归并排序的步骤

1.  **Divide（分解）**：把长度为 \(n\) 的输入序列分成两个长度为 \(n/2\) 的子序列。
2.  **Conquer（解决）**：对这两个子序列分别采用归并排序（这是一个递归的过程）。
3.  **Combine（合并）**：将两个排好序的子序列合并成一个最终的排序序列。

## 4.2 代码实现

```c
#include <stdio.h>

#define LEN 8
int a[LEN] = { 5, 2, 4, 7, 1, 3, 2, 6 };

// 合并两个已排序的子数组
void merge(int start, int mid, int end)
{
    int n1 = mid - start + 1;
    int n2 = end - mid;
    int left[n1], right[n2]; // C99 变长数组特性
    int i, j, k;

    // 将数据拷贝到临时数组
    for (i = 0; i < n1; i++) /* left holds a[start..mid] */
        left[i] = a[start+i];
    for (j = 0; j < n2; j++) /* right holds a[mid+1..end] */
        right[j] = a[mid+1+j];

    // 合并过程：每次取两个子数组中最小的元素放入原数组
    i = j = 0;
    k = start;
    while (i < n1 && j < n2)
        if (left[i] < right[j])
            a[k++] = left[i++];
        else
            a[k++] = right[j++];

    // 把剩余的元素直接拷贝回原数组
    while (i < n1) /* left[] is not exhausted */
        a[k++] = left[i++];
    while (j < n2) /* right[] is not exhausted */
        a[k++] = right[j++];
}

// 递归排序
void sort(int start, int end)
{
    int mid;
    if (start < end) {
        mid = (start + end) / 2;
        printf("sort (%d-%d, %d-%d) %d %d %d %d %d %d %d %d\n",
               start, mid, mid+1, end,
               a[0], a[1], a[2], a[3], a[4], a[5], a[6], a[7]);
        
        sort(start, mid);     // 递归排序左半部分
        sort(mid+1, end);     // 递归排序右半部分
        merge(start, mid, end); // 合并
        
        printf("merge (%d-%d, %d-%d) to %d %d %d %d %d %d %d %d\n",
               start, mid, mid+1, end,
               a[0], a[1], a[2], a[3], a[4], a[5], a[6], a[7]);
    }
}

int main(void)
{
    sort(0, LEN-1);
    return 0;
}
```

**调用过程理解**：
由于 `sort` 函数递归调用了自己两次，控制流沿虚线方向调用和返回，各函数之间的调用关系呈现**树状结构**。理解递归函数时，不要将整棵树完全展开来看，要抓住 **Base Case** 和 **递推关系** 来理解。

## 4.3 时间复杂度的严谨分析

### 1. `merge` 函数的复杂度
假设子序列 `a[start..mid]` 的长度为 \(n_1\)，子序列 `a[mid+1..end]` 的长度为 \(n_2\)，`a[start..end]` 的总长度为 \(n = n_1 + n_2\)。
前两个 `for` 循环的执行时间是 \(\Theta(n_1+n_2)\)，也就是 \(\Theta(n)\)。
后面三个 `while` 循环合在一起，每走一次循环就会在最终的排序序列中确定一个元素，所以总共执行 \(n\) 次。
因此，`merge` 函数总执行时间是 \(\Theta(n)\)。

### 2. `sort` 函数的复杂度
设输入长度为 \(n\) 的 `sort` 函数的执行时间为 \(T(n)\)。
*   当输入长度 \(n=1\) 时（即 `start == end`），`if` 条件不成立，执行时间为常数 \(\Theta(1)\)。
*   当 \(n>1\) 时，总执行时间 = 2次长度为 \(n/2\) 的 `sort` 函数的执行时间 + `merge` 函数的执行时间 \(\Theta(n)\)。

得出递推公式（Recurrence）：
\[
T(n) = \begin{cases} \Theta(1) & \text{if } n=1 \\ 2T(n/2) + \Theta(n) & \text{if } n>1 \end{cases}
\]

### 3. 递归树（Recursion Tree）展开
我们需要消去等式右侧的 \(T(n)\)，把 \(T(n)\) 写成 \(n\) 的函数。
设 \(T(n) = 2T(n/2) + cn\)（取常数 \(c\) 作为上界），将其展开：
*   **第1层**：代价为 \(cn\)。
*   **第2层**：展开为两个 \(T(n/2)\)，每个提供 \(c(n/2)\) 的代价，合计 \(cn\)。
*   **第3层**：展开为四个 \(T(n/4)\)，每个提供 \(c(n/4)\) 的代价，合计 \(cn\)。
*   ...
*   **第 \(k\) 层**：共有 \(2^k\) 个节点，每个节点代价为 \(c(n/2^k)\)，该层总代价仍为 \(cn\)。

递归树的总高度是多少？当子问题规模缩小到 1 时结束，即 \(n/2^k = 1\)，解得 \(k = \log_2 n\)。
所以树的高度约为 \(\log n\)，共有 \(\log n + 1\) 层。每一层的代价都是 \(cn\)。

总执行时间 = 所有层代价之和：
\(T(n) = cn(\log n + 1) = cn\log n + cn\)

忽略低阶项 \(cn\)，\(T(n)\) 的上界为 **\(\Theta(n\log n)\)**。
同理，取较小的常数求下界也是 \(\Theta(n\log n)\)。所以归并排序的时间复杂度是 **\(\Theta(n\log n)\)**。

### 4. 与插入排序的比较
对于较大的输入长度 \(n\)，\(n\log n\) 的增长速度远小于 \(n^2\)。因此归并排序比插入排序快得多。
**但是**，归并排序引入了较大的常数系数和空间开销（需要分配临时数组 `left` 和 `right`），在极小规模的数据下，插入排序可能反而更快。这也是很多标准库在底层实现排序时，会结合两者（数据量小时用插入，大时用归并/快排）的原因。

## 4.4 课后习题：快速排序

快速排序（Quicksort）是另一种采用分而治之策略的排序算法，平均情况时间复杂度也是 \(O(n\log n)\)，但比归并排序有更小的时间常数。

**核心逻辑**：选取一个基准元素（pivot），将数组分成两半，左边都比 pivot 小，右边都比 pivot 大。然后再递归调用。

**补全 `partition` 函数的逻辑**：
```c
int partition(int start, int end)
{
    int pivot = a[start]; // 选第一个元素作为基准
    int i = start, j = end;
    
    while (i < j) {
        // 从右向左找小于 pivot 的数
        while (i < j && a[j] >= pivot) j--;
        if (i < j) a[i++] = a[j];
        
        // 从左向右找大于 pivot 的数
        while (i < j && a[i] <= pivot) i++;
        if (i < j) a[j--] = a[i];
    }
    a[i] = pivot; // 将 pivot 放到最终位置
    return i;
}
```

**快排的复杂度**：
*   **最好情况**：每次划分都将数组均分，类似归并排序，时间复杂度为 \(\Theta(n\log n)\)。
*   **最坏情况**：数组已经是正序或逆序，每次划分只能分出一个元素，退化为类似插入排序的 \(O(n^2)\)。
*   **平均情况**：通过随机化 pivot，期望时间复杂度为 \(\Theta(n\log n)\)。


# 5. 线性查找

有些查找问题要用时间复杂度为 \(O(n)\) 的算法来解决。例如写一个 `indexof` 函数，从任意输入字符串中找出某个字母的位置并返回这个位置，如果找不到就返回 -1。

## 5.1 基础实现（例 11.3）

```c
#include <stdio.h>

char a[] = "hello world";

int indexof(char letter)
{
    int i = 0;
    while (a[i] != '\0') {
        if (a[i] == letter)
            return i;
        i++;
    }
    return -1;
}

int main(void)
{
    printf("%d %d\n", indexof('o'), indexof('z'));
    return 0;
}
```
这个实现是最直观和最容易想到的，时间复杂度为 \(O(n)\)。

**核心思考**：
既然插入排序不如归并排序快，那么对于“给定一个随机排列的序列，找出其中某个元素的位置”这个问题，**有没有比 \(O(n)\) 更快的算法？比如 \(O(\log n)\)？**
答案是**没有**（除非序列是有序的，可以使用二分查找）。因为如果序列是无序的，你没有任何捷径，在最坏情况下，你**必须把每一个元素都看一遍**，才能确定你要找的元素是不是在最后一个位置，或者是不是根本不存在。

---

## 5.2 进阶思考：找第 k 小元素（Top-K 问题）

基于上面的结论，我们来看一组寻找极值的题目。

**习题 1**：在一组随机排列的数中找出最小的一个。
*   **直观解法**：\(O(n)\)。遍历一遍，用一个变量记录当前最小值，遇到更小的就更新。
*   **有没有比 \(O(n)\) 更快的？** 没有。因为如果你不全看一遍，你怎么知道漏掉的那个数是不是最小的？

**习题 2**：找出第二小的数。
*   **直观解法**：\(O(n)\)。可以遍历两遍（第一遍找最小，第二遍找次小），或者在遍历一遍的过程中同时记录最小和次小。依然无法比 \(O(n)\) 更快。

**习题 3（进阶）**：在一组随机排列的数中找出第 \(k\) 小的数。这个元素称为 **K-th Order Statistic（第 k 顺序统计量）**。
*   **最直观的算法**：先排序，再取第 \(k\) 个。时间复杂度等于排序的复杂度 \(O(n\log n)\)。
*   **更优的算法**：利用上一节快排中的 `partition` 思想，可以将平均时间复杂度降低到 **\(O(n)\)**。

### 实现快速选择算法（Quickselect）

快速选择算法的核心思想是：
1.  用 `partition` 函数把序列分成两半，中间的 `pivot` 元素是序列中的第 `i` 个（假设从 0 开始计数）。
2.  如果 `k == i`，恭喜你，找到了！
3.  如果 `k < i`，说明第 `k` 小的元素在左半部分，去左边找。
4.  如果 `k > i`，说明第 `k` 小的元素在右半部分，去右边找。（注意：**此时不需要对两边都递归，只需要递归包含目标的那一半**）。

**完整 C 语言代码实现**：

```c
#include <stdio.h>

// 复用之前的 partition 函数（挖坑法）
int partition(int a[], int start, int end)
{
    int pivot = a[start]; 
    int i = start;
    int j = end;

    while (i < j) {
        while (i < j && a[j] >= pivot) j--;
        if (i < j) {
            a[i] = a[j];
            i++; 
        }
        while (i < j && a[i] <= pivot) i++;
        if (i < j) {
            a[j] = a[i];
            j--;
        }
    }
    a[i] = pivot;
    return i; 
}

/* 从 start 到 end 之间找出下标为 k 的元素 */
int order_statistic(int a[], int start, int end, int k)
{
    if (start == end) {
        return a[start]; // 只有一个元素，直接返回
    }

    // 用 partition 把序列分成两半
    int mid = partition(a, start, end);

    if (k == mid) {
        // 如果 k 正好等于中间元素的下标，直接返回
        return a[mid];
    } else if (k < mid) {
        // 如果 k 在左半部分，去左半边找
        return order_statistic(a, start, mid - 1, k);
    } else {
        // 如果 k 在右半部分，去右半边找
        return order_statistic(a, mid + 1, end, k);
    }
}

int main(void)
{
    int a[] = { 10, 5, 8, 2, 7, 3, 9, 1, 6, 4 };
    int len = sizeof(a) / sizeof(a[0]);
    
    // 找第 3 小的数 (假设下标从 0 开始，即找排序后下标为 2 的元素)
    int target_index = 2; 
    int result = order_statistic(a, 0, len - 1, target_index);
    
    printf("The 3rd smallest element is: %d\n", result);
    
    return 0;
}
```

### 为什么快速选择的平均时间复杂度是 \(O(n)\)？

回顾快速排序，时间复杂度是 \(O(n\log n)\)，因为它每次划分后，**左右两半都要继续递归处理**。

而快速选择，每次 `partition` 后，我们**只往包含目标 `k` 的那一半递归**，另一半直接丢弃。
*   第 1 次划分：遍历 \(n\) 个元素。
*   第 2 次划分：遍历 \(n/2\) 个元素（假设平分）。
*   第 3 次划分：遍历 \(n/4\) 个元素。
*   ...

总的时间消耗是：\(n + \frac{n}{2} + \frac{n}{4} + \frac{n}{8} + ...\)
这是一个等比数列求和，根据数学公式，当 \(n\) 趋于无穷大时，这个和趋近于 **\(2n\)**。

忽略常数项，快速选择的平均时间复杂度就是 **\(O(n)\)**。
这就是算法设计的魅力：**仅仅通过改变递归的策略（只递归一边），就把时间复杂度从 \(O(nlog n)\) 降到了 \(O(n)\)。**


# 6. 折半查找

如果是从一组**排好序**的序列里找出某个元素的位置，则可以使用比线性查找更快的算法：**折半查找（Binary Search）**。

## 6.1 算法核心与实现

**基本思想**：每次取中间的元素和待查找的元素比较。如果中间的元素比待查找的元素小，说明目标元素在右半部分；反之在左半部分。每次将搜索范围缩小一半。时间复杂度为 **\(O(\log n)\)**。

```c
#include <stdio.h>

#define LEN 8
int a[LEN] = { 1, 2, 2, 2, 5, 6, 8, 9 };

int binarysearch(int number)
{
    int mid, start = 0, end = LEN - 1;

    while (start <= end) {
        mid = (start + end) / 2;
        if (a[mid] < number)
            start = mid + 1;
        else if (a[mid] > number)
            end = mid - 1;
        else
            return mid;
    }
    return -1;
}
```

**易错点（死循环陷阱）**：
*   更新区间时必须是 `start = mid + 1` 和 `end = mid - 1`。
*   如果错写成 `start = mid` 或 `end = mid`，在 `start` 和 `end` 相邻时，`mid` 的计算会陷入死循环。

## 6.2 正确性证明与契约式编程

### 1. 循环不变量（Loop Invariant）
可以用 Loop Invariant 来证明 `binarysearch` 的正确性。
定义条件 `mustbe(start, end, number)`：**待查找的元素 `number` 如果存在于数组 `a` 之中，那么一定存在于 `a[start...end]` 这个范围之间。**
*   **初始化**：刚开始 `start=0`, `end=LEN-1`，`mustbe` 显然成立。
*   **保持**：每次循环通过比较 `a[mid]` 和 `number` 更新 `start` 或 `end`，依然维护了 `mustbe` 的成立。
*   **终止**：当 `start > end` 时循环结束，此时 `a[start...end]` 是空区间，说明目标元素一定不在整个数组中，返回 `-1` 是正确的。

### 2. 契约式设计（Design by Contract, DbC）
由 Eiffel 语言设计者 Bertrand Meyer 提出。函数调用者（Caller）和实现者（Callee）之间订立契约：
*   **前置条件（Precondition）**：调用者必须提供的条件。如：**必须保证数组 `a` 是排好序的**。
*   **后置条件（Postcondition）**：实现者必须完成的任务。如：如果 `number` 存在，必须返回其位置；如果不存在，必须返回 -1。
*   **不变量（Invariant）**：如 Loop Invariant，在运行过程中必须始终保持为真的条件。

## 6.3 断言（Assertion）与测试

在开发阶段，使用 `assert` 宏可以有效地帮助测试程序，验证前置/后置条件是否满足。

*   **头文件**：`#include <assert.h>`
*   **用法**：`assert(表达式)`。如果表达式为真，什么也不做；如果为假，程序会报错并终止（`Aborted`）。

**在折半查找中插入断言**：
```c
#include <stdio.h>
#include <assert.h>

// 辅助函数：判断数组是否已排序
int is_sorted(void) { ... } 
// 辅助函数：判断 number 是否在区间外
int mustbe(int start, int end, int number) { ... }
// 辅助函数：判断 number 是否在数组内
int contains(int n) { ... }

int binarysearch(int number)
{
    int mid, start = 0, end = LEN - 1;

    assert(is_sorted()); /* Precondition: 断言数组是有序的 */

    while (start <= end) {
        assert(mustbe(start, end, number)); /* Maintenance: 断言区间维护正确 */
        
        mid = (start + end) / 2;
        if (a[mid] < number)
            start = mid + 1;
        else if (a[mid] > number)
            end = mid - 1;
        else {
            assert(mid >= start && mid <= end && a[mid] == number); /* Postcondition 1 */
            return mid;
        }
    }
    assert(!contains(number)); /* Postcondition 2: 断言没找到 */
    return -1;
}
```

**禁用断言（Release 版本）**：
测试代码只在开发和调试时有用。正式发布（Release）时如果还运行断言，会严重影响性能。
在包含 `<assert.h>` 之前定义宏 `#define NDEBUG`，或者编译时加 `-DNDEBUG` 参数，就可以禁用所有的 `assert` 检查。

## 6.4 课后习题思路

**1. 查找返回第一个匹配项**
如果数组中有多个相同的目标元素，折半查找默认返回其中任意一个。若要返回第一个，需修改 `else` 分支逻辑：
当 `a[mid] == number` 时，不要立刻 `return mid`，而是记录当前的位置，并把 `end` 更新为 `mid - 1`，继续向左半边查找，直到循环结束，最后返回记录的位置。

**2. 用折半查找求平方根 `mysqrt(y)`**
*   **思路**：在 `[0, y]` 区间内找，`mid * mid` 与 `y` 比较。
*   **终止条件**：因为浮点数不能直接判断相等，需要设定精度，如 `if (mid * mid - y < 0.001 && mid * mid - y > -0.001)` 就可以认为找到了。
*   **迭代次数**：由要求的精度决定。精度越高，折半的次数越多。

**3. 快速幂 `mypow(x, n)`**  
计算 \(x^n\)。普通的循环乘法时间复杂度是 \(O(n)\)。利用折半思想（分治）可以降到 \(O(\log n)\)。
*   如果 \(n\) 是偶数：\(x^n = (x^{n/2})^2\)
*   如果 \(n\) 是奇数：\(x^n = x \times (x^{n/2})^2\)
*   递归实现：`return mypow(x, n/2) * mypow(x, n/2);` （注意处理奇数情况）
*   循环实现（非递归）：利用二进制位运算，从低位到高位扫描 \(n\) 的二进制位，不断对 \(x\) 进行平方。
