# 1. C语言数学函数知识点

## 1.1 文件引入与编译链接

- 头文件：使用数学函数（(\sin)、log 等）必须包含 `<math.h>`，标准输入输出（printf）需包含 `<stdio.h>`。
- 编译选项：Linux 下 gcc 编译时，数学函数位于 libm.so，需加 `-lm`（如 `gcc main.c -lm`）；常规函数（如 printf 位于 shturl.）默认链接，无需额外选项。

## 1.2 常见函数与调用规则

- 对应关系：数学上的 $\(\ln)$ 对应 C 语言的 `log`（自然对数），$\(\sin)$ 对应 `\(\sin\)`。
- 语法强制：C 语言函数调用必须加括号（如 `log(1.0)`），不可像数学书写那样省略。

代码示例：

```
#include <math.h>
#include <stdio.h>
int main(void) {
    double pi = 3.1416;
    printf("\(\sin\)(pi/2)=%f\n\(\ln\)1=%f\n", \(\sin\)(pi/2), log(1.0));
    return 0;
}
```

## 1.3 函数调用与表达式

核心术语：

- 参数（Argument）：传入值（如 1.0）。
- 函数名（Function Designator）：如 `log`。
- 函数调用（Function Call）：如 `log(1.0)`，由函数名与参数组成。
- 返回值（Return Value）：调用结果（如 `log(1.0)` 返回 0.0），通常为 double 型。

语法规则：

```
表达式 → 函数名
表达式 → 表达式(参数列表)
参数列表 → 表达式, ...
```

本质：函数调用本身也是表达式，printf 调用同样是表达式语句（返回打印字符数，常被忽略）。

## 1.4 副作用（Side Effect）

概念：C 函数不仅返回数值，常产生副作用（改变状态或执行 I/O）。

典型场景：

- `printf`：主要利用副作用打印输出，而非获取返回值。
- 赋值（`a = b`）：返回赋的值，副作用是改变变量 a（修改内存）。
- 运算（`a + b`）：仅返回值，无副作用。

本质区别：数学函数侧重返回值，C 语言函数常结合返回值与副作用。

## 1.5 头文件与库函数

- 头文件：声明函数、宏等，遵循“先声明后使用”，系统头文件常在 `/usr/include`。
- 库文件：
  - shturl.：C 标准库（含 printf），默认链接。
  - libm.so：数学库（含 (\sin)、log），需 `-lm` 显式链接。
- 无库调用：极简程序（如仅 `return 0;`）可无头文件编译，但无实际库功能。

## 1.6 C标准库与 glibc（Linux）

- C标准：包含语法 + 标准库（头文件、函数等）。
- glibc：Linux 最广泛 C 函数库，实现标准库及系统函数：
  - shturl.：基础标准库，几乎所有程序依赖。
  - libm.so：数学库。
  - libpthread.so：多线程库。
  - 其他：嵌入式可能用 uClibc，glibc 是主流基础。

## 1.7 学习认知的泛化

学习从严格到泛化：赋值语句 → 表达式语句；printf 从“语句”泛化为“表达式语句”。
概念随认知深化修正（如数系扩展），当前简化理解是必经阶段。

> 
> 核心速记：用 `<math.h>` 调 (\sin)/log，编译加 `-lm`；函数调用是表达式，有返回值；printf/赋值重在副作用；glibc 是 Linux C 库核心，libc 默认链，libm 需显式链。


# 2. 自定义函数

## 2.1 函数定义与语法规则
- **基本形式**：`返回值类型 函数名(参数列表) 函数体`
- **语法推导**：
  - 函数定义 → 返回值类型 函数名(参数列表) 函数体
  - 函数体 → `{ 语句列表 }`
  - 语句列表 → 语句 | 语句列表 语句
  - 非定义的函数声明 → 返回值类型 函数名(参数列表);
- **main函数特殊性**：
  - 由操作系统自动调用，名字特殊，其余与普通函数无异。
  - 参数常写 `void`（标准写法为 `int main(int argc, char *argv[])`，也可写 `int main(void)`）。
  - 返回值给操作系统：`return 0` 表示成功，非零表示出错（可通过 Shell 的 `$?` 查看退出状态）。
  - **避免旧式写法**：`main()`（不写返回值和参数）是 Old Style C，虽兼容但不推荐。

## 2.2 简单自定义函数与副作用（Side Effect）
- **无参无返回值**：如 `void newline(void) { printf("\n"); }`，`void` 表示无返回值，调用它完全是为了利用**打印换行**的副作用。
- **函数嵌套调用**：可在一个函数中调用另一个函数，如 `threeline()` 内部连续调用三次 `newline()`。
- **自定义函数优势**：
  1. 同一函数可多次调用。
  2. 函数间可相互调用，隐藏复杂操作。
  3. 使代码更简洁（如用 `threeline()` 替代多次写 `printf`）。

## 2.3 执行顺序与调用栈
- **阅读顺序**：按代码执行流（非单纯从上到下），先执行 `main`，遇到调用跳转到对应函数，执行完返回原处。
- **调用关系**：`main` → `threeline` → `newline`（多次），需记住“从哪调用，返回哪继续”。

## 2.4 函数原型（Prototype）与声明
- **概念区分**：
  - **函数声明**：仅说明名字、参数、返回值（可带函数体，也可不带）。
  - **函数定义**：包含函数体，分配存储空间，生成指令。
  - **函数原型**：明确的声明（指定参数类型、个数、返回值），如 `void threeline(void);`。
- **先声明后使用**：
  - 若函数在调用前未定义，必须提前写**函数原型**，否则编译器无法检查参数。
  - 写原型后可改变函数定义顺序（如 `main` 写在最前，其它函数定义在后）。
- **隐式声明（Implicit Declaration）**：
  - 若调用前无任何声明，编译器默认隐式声明为 `int 函数名(void)`。
  - 若后续定义与隐式声明不符（如实际返回 `void`），会报 `conflicting types` 警告，但可能仍能运行（不推荐）。
- **Old Style C 声明**：
  - 如 `void threeline();` 未明确参数，不算原型，编译器不检查参数类型/个数，易引入 Bug，绝不推荐新代码使用。

## 2.5 返回值与 void 补充
- `void` 表示“无返回值”，调用此类函数仅用其副作用。
- 语法上无返回值的调用也有“值”（为 `void` 类型），但语义上不能参与运算（如 `newline() + 1` 报错），兼顾语法一致与语义限制。

# 3. 形参和实参

## 3.1 带参数函数的声明与定义

- **定义规则**：定义带参函数时，必须指明参数个数和每个参数的类型。定义参数就像定义变量，必须逐个指明类型。
- **错误示范**：普通变量定义支持同类型并列（如 `int a, b;`），但函数参数定义不支持这种简写。例如 `void f(int hour, minute)` 是错误写法，`minute` 未显式指定类型。
- **正确代码示例**：

```
void print_time(int hour, int minute) {
    printf("%d:%d ", hour, minute);
}
```

## 3.2 形参、实参与值传递（Call by Value）

### 基本概念

- **形参（Parameter）**：函数定义中的参数（例如上例中的 `hour`），相当于函数内部定义的局部变量。
- **实参（Argument）**：调用函数时传入的具体值或变量（例如调用时传入的 `23` 或变量 `h`）。

### 传递原理

调用函数传递参数的过程，本质上是**用实参给形参做初始化**，等价于在函数入口执行了 `int hour = h;` 这样的赋值操作。

### 值传递特性

C语言默认采用 **Call by Value（值传递）**：
形参和实参是两个完全独立的变量，仅仅保存了相同的数值。在函数内部修改形参的值，**不会影响外部的实参**。

### 调用规则

实参的个数、类型必须与形参严格对应，不能多也不能少。

## 3.3 可变参数与接口（Interface）

- **可变参数**：C语言允许使用 `...` 表示0个或任意多个参数，例如 `printf` 的函数原型为：
```c
int printf(const char *format, ...);
```
- **接口概念**：函数原型明确规定了返回值类型和参数的类型、个数，这就是函数的**接口**。调用函数必须与接口规范保持一致。

## 3.4 Man Page 基础（Linux）

- **概念**：Linux开发环境最常用的官方参考手册，按主题分类组织。
- **常用Section（章节分类）**：
  1. Section 1：用户命令（如 `ls(1)`）
  2. Section 2：系统调用（如 `_exit(2)`）
  3. Section 3：库函数（如 `printf(3)`）
  4. Section 4：特殊文件（如 `null(4)`）
  5. Section 5：系统配置文件格式（如 `passwd(5)`）
  6. Section 6：游戏
  7. Section 7：其它杂项（如 `bash-builtins(7)`）
  8. Section 8：系统管理命令（如 `ifconfig(8)`）
- **使用技巧**：遇到重名时，用数字指定章节精准查询。例如 `man 3 printf` 查询库函数版本的printf；直接执行 `man printf` 默认优先查询用户命令章节。

## 3.5 习题解析

### 值传递测试

- **问题**：调用 `increment(i)` 能否让外部变量 `i` 加1？
```c
void increment(int x)
{
	x = x + 1;
}

int main(void)
{
	int i = 1, j = 2;
	increment(i); /* i now becomes 2 */
	increment(j); /* j now becomes 3 */
	return 0;
}
```
- **答案**：不能。因为C语言默认是值传递，函数内部修改的只是形参的副本，外部的实参 `i` 不会被改变。

### 隐式声明分析

- **问题**：不包含头文件就调用 `printf`，报错 `incompatible implicit declaration`，原因是什么？
- **原因**：未包含 `<stdio.h>` 时，编译器第一次遇到 `printf` 会进行隐式声明（默认返回 `int`、无参数），与标准库中 `printf` 的真实原型（返回 `int` 但为可变参数）冲突，进而产生警告/错误。

> 
> **核心速记**：定义函数参数必须逐个指明类型；形参是函数内的局部变量，实参是调用时传入的值；C语言默认值传递，修改形参不影响实参；函数原型就是函数的接口；查C库函数用 `man 3`。

# 4. 全局变量、局部变量和作用域

## 4.1 局部变量（Local Variable）
- **定义位置**：在函数内部定义的变量，函数的形参也属于局部变量范畴。
- **作用域限制**：只能在定义它的函数内部使用，其他函数无法直接访问。例如 `main` 中的局部变量，不能被 `print_time` 函数使用。
- **存储与生命周期**：
  - 每次函数调用时为局部变量分配存储空间，函数执行返回时空间自动释放。
  - 不同函数中的同名局部变量，代表完全独立的不同存储单元，互不影响。
- **未初始化状态**：局部变量未手动初始化时，初始值是不确定的（内存中的残留垃圾值），使用前必须显式赋值。

## 4.2 全局变量（Global Variable）
- **定义位置**：定义在所有函数体之外的变量。
- **作用域**：从定义位置开始一直到源文件结束，范围内的任何函数都可以直接访问。
- **存储与生命周期**：程序开始运行时分配存储空间，整个运行期间持续存在，程序结束时才释放。
- **未初始化状态**：全局变量未手动初始化时，系统默认初始值为 `0`。
- **使用建议**：全局变量读写时序不直观、隐蔽性强，容易引入难以调试的 Bug。应当慎用全局变量，能用函数传参实现的逻辑就不要使用全局变量。

## 4.3 作用域与变量重名（覆盖规则）
- **覆盖规则**：如果局部变量与全局变量重名，在局部变量的作用域范围内，**局部变量生效，全局变量被“遮蔽”**。
- **形象比喻：大纸与小纸**
  - 全局变量的作用域像一张铺满整个源文件的大纸。
  - 函数局部变量的作用域像盖在大纸上的小纸，仅覆盖函数内部区域。
  - 查找标识符时，先在当前小纸上查找；找不到，才会去下层的大纸上查找。
- **局部作用域的函数声明**：函数声明也可以写在局部作用域中（例如写在 `main` 内部），此时该函数名仅在当前函数内有效。

## 4.4 变量初始化规则
- **局部变量初始化**：可以用类型相符的任意表达式初始化，甚至可以用函数返回值，例如 `double pi = acos(-1.0);`。
- **全局变量初始化**：只能用**常量表达式（Constant Expression）** 初始化。
  - 原因：全局变量的初始值在程序运行前（编译阶段）就必须确定，并固化在可执行文件中。
  - 错误示例：
    ```c
    int minute = 60;
    int hour = minute / 60;  // 非法，minute 是变量，非常量表达式
    ```

## 4.5 局部变量生命周期验证与误区
- **实验现象**：连续两次调用同一个含未初始化局部变量的函数，第二次调用可能打印出第一次修改后的值（例如 777）。
- **逻辑推理**：
  - “局部变量不初始化则初值不确定”是**必要条件，不是充分条件**。
  - 观察到两次值相同，不能反推出“局部变量有固定存储空间、不会释放”。
  - 若在两次调用中间插入其他函数调用（例如 `printf`），栈内存会被覆盖，第二次打印的值就会变为 0 或其他随机值。
- **初学者警示**：不要凭主观现象给问题定性，应当尊重客观规则和逻辑推理，未初始化的局部变量始终是不安全的。

## 4.6 函数声明与作用域补充
- **局部函数声明**：函数声明可以写在局部作用域内（例如某个函数内部），此时该函数名仅在该作用域内可见、有效。
- **嵌套定义限制**：标准 C 语言**不允许嵌套定义函数**（即在一个函数内部定义另一个函数）；GNU C（gcc）有扩展特性支持嵌套函数定义，但不属于标准语法，不推荐使用。

> **核心速记**：
> - 局部变量在函数内，调用分配、返回释放，未初始化值不确定；
> - 全局变量在函数外，程序启动分配、结束释放，未初始化默认值为0；
> - 变量重名时，局部作用域内局部变量覆盖全局变量；
> - 全局变量只能用常量表达式初始化，局部变量可用任意表达式初始化。
