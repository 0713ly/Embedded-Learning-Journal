# 1. 整型与整数常量

C 语言中的整型（Integer）在不同平台和编译器下可能存在差异。C 标准并没有规定所有细节，这导致了一些容易踩坑的陷阱。

## 1.1 整型的符号性与长度

### 1. `char` 类型的符号性
C 语言规定的 `signed` 和 `unsigned` 关键字用于表示有无符号数。
*   `unsigned char`：无符号，范围 `0~255`（8 bit）。
*   `signed char`：有符号（采用 2's Complement），范围 `-128~127`。
*   **不带 `signed` 或 `unsigned` 的 `char`**：C 标准规定为 **Implementation Defined（实现定义）**。编译器可以将其定义为有符号或无符号（x86 平台的 gcc 默认为**有符号**）。
*   **建议**：如果只是存 ASCII 码，无所谓符号；如果作为 8 位整数使用，为了可移植性，必须明确写出 `signed` 或 `unsigned`。

> **? 补充概念：三种“未明确规定”**
> *   **Implementation-defined（实现定义）**：C 标准未规定，但要求编译器必须做出规定，并在文档中写明（如 `char` 的符号性）。
> *   **Unspecified（未指定）**：编译器可自行决定，且不必写入文档（如函数参数的求值顺序）。
> *   **Undefined（未定义）**：标准完全没规定，编译器可能不报错，但运行结果完全不可控（如数组越界）。

### 2. 其他整型类型与长度
除 `char` 外，`short`、`int`、`long`、`long long` **如果不写 `signed` 或 `unsigned`，默认都是 `signed`**。
不同数据类型占用的字节数（长度）也是 Implementation-defined。目前主流的有两种模型：

| 类型 | ILP32 (32位系统) | LP64 (64位系统) |
| :--- | :--- | :--- |
| `char` | 8 bits | 8 bits |
| `short` | 16 bits | 16 bits |
| `int` | 32 bits | 32 bits |
| `long` | **32 bits** | **64 bits** |
| `long long` | 64 bits | 64 bits |
| 指针 (Pointer) | 32 bits | 64 bits |

## 1.2 整数常量的表示法

除了十进制，C 语言还支持八进制和十六进制：
*   **十进制**：不能以 `0` 开头。
*   **八进制**：以 `0` 开头，如 `022`。
*   **十六进制**：以 `0x` 或 `0X` 开头，如 `0x1A`。

## 1.3 整数常量的后缀与类型推导

整数常量可以加后缀来明确其类型：
*   `u` 或 `U`：表示 `unsigned`。
*   `l` 或 `L`：表示 `long`。
*   `ll` 或 `LL`：表示 `long long`。
（后缀可以组合，如 `ULL`、`llu` 等）。

**类型的推导规则（见表 15.2）**：
给定一个整数常量，编译器会根据它的**进制**和**后缀**，在一个候选类型列表中，**从上到下寻找第一个能“装下”该数值的类型**。
*   **例子 1**：`1234U`（十进制，后缀U）。候选列表为 `unsigned int`, `unsigned long`, `unsigned long long`。`unsigned int` 装得下，所以它的类型是 `unsigned int`。
*   **例子 2**：`0xffff0000`（十六进制，无后缀）。候选列表包含 `int`, `unsigned int` 等。`int` 表示不了这么大的正数（最高位为1会被当做负数），所以推导为 `unsigned int`。

## 1.4 两个经典的“坑”

### 坑 1：`-2147483648` 不是整数常量
在 32 位系统中，`int` 的范围是 `-2147483648 ~ 2147483647`。
如果你写 `printf("%d\n", -2147483648);`，编译器会警告类型不匹配。
**原因**：C 语言中没有 `-2147483648` 这个常量。它是由“负号运算符 `-`” 和 “常量 `2147483648`” 组成的表达式。因为 `2147483648` 超出了 `int` 的正数上限，它会被推导为 `long long`（C99前可能报错）。所以整个表达式也是 `long long`，用 `%d`（期望 `int`）打印就会出错。
**正确写法**：`-2147483647 - 1` 或者强转 `(int)-2147483648`。

### 坑 2：乘法运算的溢出
```c
long long i = 1234567890 * 1234567890; // 警告：integer overflow in expression
```
**原因**：参与运算的两个操作数 `1234567890` 默认推导为 `int`。两个 `int` 相乘，**结果依然是一个 `int`**。但乘积已经超出了 `int` 的范围，导致在赋值给 `long long` 之前就已经发生了截断溢出。
**正确写法**：强制将其中一个操作数变为 `long long`，让整个表达式以 `long long` 进行运算。
```c
long long i = 1234567890LL * 1234567890; 
```

# 2. 浮点型

与整型类似，C 标准规定的浮点型（`float`、`double`、`long double`）既没有规定每种类型占多少字节，也没有规定采用哪种具体的表示形式。

## 2.1 浮点型的种类与平台差异

浮点数的实现在各种平台上差异很大，主要体现在两个方面：
1.  **硬件支持**：
    *   **硬浮点（Hard-float）**：处理器带有浮点运算单元（FPU），直接在硬件层面进行浮点运算。
    *   **软浮点（Soft-float）**：处理器没有 FPU，只能用整数运算来模拟浮点运算，效率较低。
2.  **标准与长度**：大部分平台遵循 **IEEE 754** 标准。通常情况下，`float` 是 32 位，`double` 是 64 位。

## 2.2 `long double` 的特殊性

`long double` 是比 `double` 精度更高的类型，但它在各平台的实现差异最悬殊：
*   **x86 平台**：大多数编译器实现的 `long double` 是 **80 位**（因为 x86 的浮点运算单元具有 80 位精度）。
*   **gcc 实现**：gcc 将 `long double` 实现为 **12 字节（96 位）**，这是为了对齐到 4 字节边界（涉及结构体的内存对齐问题）。
*   **其他平台**：在 PowerPC 等架构上，`long double` 通常高达 **128 位**。

## 2.3 浮点数常量的表示法

浮点数在计算机中是基于科学计数法表示的，因此浮点数常量也有多种写法：

1.  **基本写法**：如 `3.14`。
2.  **科学计数法**：尾数和指数之间用 `e` 或 `E` 隔开。
    *   **注意**：这种形式的**基数是 10**。
    *   例如：`314e-2` 表示 \(314 \times 10^{-2}\)。
    *   如果尾数的小数点左边或右边没有数字，则表示该部分为 0，例如 `3.e-1`（即 \(3.0 \times 10^{-1}\)）、`.987`（即 \(0.987\)）。

**后缀与类型对应关系**：
*   **无后缀**：默认为 `double` 型（如 `3.14`）。
*   后缀 **`f` 或 `F`**：表示 `float` 型（如 `3.14f`）。
*   后缀 **`l` 或 `L`**：表示 `long double` 型（如 `3.14L`）。

> *注：C99 标准引入了一种基于基数为 2 的十六进制浮点数表示形式（如 `0x1.8p3`），但在日常编程中较为罕见。*

# 3. 类型转换

C 语言的类型转换规则非常庞大且复杂。由于不同体系结构对整数和浮点数的实现存在差异，很多转换规则属于 C 标准的“阴暗角落”（未明确定义）。了解这些规则，不仅能帮你写出更健壮的代码，更能让你在出现莫名其妙的 Bug 时，迅速找到原因。

C 语言的类型转换主要分为三种：**隐式类型转换（编译器自动完成）** 和 **强制类型转换（程序员手动指定）**。

## 3.1 Integer Promotion（整型提升）

**规则**：在一个表达式中，凡是能使用 `int` 或 `unsigned int` 类型做右值的地方，也可以使用有符号或无符号的 `char`、`short` 和 `bit-field`。
如果原始类型的取值范围能用 `int` 表示，则提升为 `int`；否则提升为 `unsigned int`。

**触发场景**：
1.  **函数形参未知**：例如 `printf` 的变长参数，或者旧式风格的函数调用。当传入 `char` 时，会自动提升为 `int`。相应的，传入的 `float` 也会被提升为 `double`（这叫 Default Argument Promotion）。
    ```c
    char ch = 'A';
    printf("%c", ch); // ch 会被提升为 int 型再传给 printf
    ```
2.  **算术运算之前**：两个 `char` 或 `short` 进行运算，会先提升为 `int`。
    ```c
    unsigned char c1 = 255, c2 = 2;
    // 如果没有提升，255+2=257 会导致 8 位无符号数溢出（变成1）。
    // 因为有整型提升，c1和c2先变成 int，相加结果为 257，赋值给 int n 完全没问题。
    int n = c1 + c2; 
    ```

## 3.2 Usual Arithmetic Conversion（寻常算术转换）

当算术运算（如 `+ - * / % > < ==` 等）两边的操作数类型不同时，编译器会自动将它们转换为相同的类型。遵循以下规则：

1.  **浮点数优先**：如果有操作数是 `long double`、`double` 或 `float`，另一个操作数也会被转换成相同类型。
2.  **整型内部规则**：如果两边都是整型，先执行 **Integer Promotion（整型提升）**。如果提升后类型仍然不同，按以下规则继续转换：
    *   **规则 a**：如果两边都是同符号（都有符号或都无符号），较低 Rank 的类型转换为较高 Rank 的类型（`char < short < int < long < long long`）。
    *   **规则 b**：如果一边是无符号数（Rank较高），另一边是有符号数（Rank较低）。有符号数转成无符号数。（非常危险，容易导致负数变超大正数）。
    *   **规则 c**：如果一边是无符号数（Rank较低），另一边是有符号数（Rank较高）。如果这个有符号类型能完全覆盖无符号类型的范围，则无符号转有符号；否则，双方都转换成无符号类型。

> ? **核心警告**：不要依赖这些复杂的规则，这属于“阴暗角落”。**在代码中尽量避免有符号数和无符号数混合运算！**

## 3.3 由赋值产生的类型转换

如果赋值（`=`）或初始化时等号两边的类型不同，编译器会把右边的类型转换成等号左边的类型。函数传参（相当于初始化）和函数返回（相当于赋值）也适用此规则。

*   **坑点**：`char c = getchar();` 中，`getchar()` 的返回值其实是 `int` 型，赋值给 `char` 会发生截断。

## 3.4 强制类型转换（Type Cast）

程序员手动指定转换的类型，格式为 `(类型名)表达式`。
*   **注意**：强制类型转换是由**单目运算符**组成的。例如 `(double)3 + 1`，`3` 会被转成 `double`，然后再和 `1` 相加，整个表达式最终类型是 `double`。

## 3.5 编译器如何处理类型转换（底层原理）

把一个 M 位的类型（值为 X）转换成 N 位的类型，底层发生的变化如下表（核心规则）：

| 转换类型 (M -> N) | M > N (变窄/截断) | M == N (同宽) | M < N (变宽/扩展) |
| :--- | :--- | :--- | :--- |
| **signed -> signed** | 截断。结果 Implementation-defined (通常保留低位) | 值不变 | **符号扩展**：高位补符号位 (0或1)，值不变 |
| **unsigned -> signed** | 截断。超出目标范围则 Implementation-defined | 超出范围则 Implementation-defined | 值不变 (高位补0) |
| **signed -> unsigned** | `X % 2^N` (底层二进制位不变，解释方式改变) | 同左 | 同左 |
| **unsigned -> unsigned**| 截断 (保留低 N 位) | 值不变 | 值不变 (高位补0) |
| **float -> int** | **向零截断** (去掉小数部分)。如果整数部分超出目标范围，**Undefined** | 同左 | 同左 |
| **int -> float** | 值可能不变，但可能**丢失精度**。超出范围则 **Undefined** | 同左 | 同左 |
| **float -> float** | 可能丢失精度。超出范围则 **Undefined** | 值不变 | 值不变 |

**关键点解析**：
1.  **符号扩展（Sign Extension）**：当短的有符号整型（如 `short` 的 `-1`，二进制全 `1`）转换为长的整型（如 `int`）时，高位必须补 `1`，才能保持值依然为 `-1`。而无符号数转长整型时，高位一律补 `0`（Zero Extension）。
2.  **向零截断（Truncate toward Zero）**：浮点数转整数时，直接丢弃小数部分。比如 `3.9` 变 `3`，`-3.9` 变 `-3`。这**不是**四舍五入。
3.  **Undefined（未定义）**：如果转换时数值超出了目标类型的表示范围（比如把 `32768.4` 强转成 `short`，或者把极大的浮点数转成 `int`），C 标准不规定会发生什么，程序可能会崩溃或产生极其诡异的垃圾值。编译器通常会给出警告。
