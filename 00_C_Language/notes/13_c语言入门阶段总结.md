# 1 C 的语法规则

**1.1 源文件中所有函数定义之外可以出现哪些语法元素？**
*   **预处理指令**：如 `#include`（引入头文件）、`#define`（宏定义）。
*   **全局变量声明/定义**：如 `int global_var = 0;`。
*   **自定义类型定义**：如 `struct`、`union`、`enum`、`typedef`。
*   **函数声明（原型）**：如 `int add(int a, int b);`，告诉编译器函数的格式。

**1.2 函数定义之中可以出现哪些语法元素？**
*   **局部变量定义**：如 `int i = 0;`。
*   **各种语句**：包括表达式语句、控制流语句（`if`, `for`, `while`）、复合语句（代码块 `{}`）。
*   **函数调用**：调用其他函数。
*   **注释**。

**1.3 语句有哪几种？**
*   **空语句**：`;`（什么都不做，常用于循环占位）。
*   **表达式语句**：如 `a = b + c;`、函数调用 `printf("hi");`。
*   **复合语句（代码块）**：用 `{}` 括起来的一组语句。
*   **控制语句**：`if/else`, `switch`, `for`, `while`, `do/while`, `break`, `continue`, `return`, `goto`。

**1.4 哪些语法元素需要遵循标识符的命名规则？**  
变量名、函数名、结构体/联合体/枚举的标签名、`typedef` 定义的类型名。

**1.5 表达式由哪些语法元素组成？**  
由 **操作数**（常量、变量、函数调用）和 **运算符** 组成，可以使用圆括号 `()` 改变计算优先级。

**1.6 到目前为止学过哪些运算符？优先级和结合性怎样？**
*   **优先级（从高到低）**：后缀（`()`, `[]`, `->`, `.`, `++`, `--`） > 单目（`!`, `~`, `++`, `--`, `+`, `-`, `*`, `&`, `sizeof`） > 算术（`* / %`，然后 `+ -`） > 移位（`<< >>`） > 关系（`< > <= >=`） > 相等（`== !=`） > 位与（`&`） > 位异或（`^`） > 位或（`|`） > 逻辑与（`&&`） > 逻辑或（`||`） > 条件（`?:`） > 赋值（`= +=` 等） > 逗号（`,`）。
*   **结合性**：大多数从左向右；单目运算符、条件运算符、赋值运算符从右向左。

**1.7 哪些运算符取操作数的左值？哪些必须是整型？哪些有 Side Effect？**
*   **取左值**：`++`, `--`, `&`（取地址符）。
*   **必须是整型**：`%`, `<<`, `>>`, `&`, `|`, `^`, `~`，以及数组下标 `[]`。
*   **有 Side Effect（副作用，即改变了变量的值）**：`++`, `--`，以及所有赋值运算符（`=`, `+=`, `*=` 等）。

**1.8 哪些表达式可以做左值？哪些只能做右值？**
*   **可做左值**（能放在等号左边被赋值）：变量名、数组元素 `a[i]`、结构体成员 `s.a`、指针解引用 `*p`。
*   **只能做右值**：常量（`10`、`"abc"`）、表达式的结果（`a + b`）、函数返回值。

**1.9 哪些地方必须用常量表达式？哪些必须用整数常量表达式？**
*   **必须用常量表达式**：全局变量的初始化值、`case` 标签后的值、`enum` 枚举成员的值。
*   **必须用整数常量表达式**：数组的定义长度（如 `int a[10];` 中的 10）、位域的宽度。

# 2 思维方法与编程思想

*   **以概念为中心**：学编程先弄懂“变量”、“类型”、“指针”等核心概念，再谈语法。
*   **组合规则**：复杂表达式是由基础表达式通过运算符和括号组合而成的。
*   **Least Surprise（最小惊吓原则）**：代码的行为应符合直觉。比如别把判断相等的 `==` 写成赋值的 `=`。
*   **充分条件与必要条件**：在 `if (i < LEN && a[i] > 0)` 中，`i < LEN` 是 `a[i]` 不越界的必要条件。利用 `&&` 的短路求值特性保护数组。
*   **封装**：将底层的数组或复杂逻辑用 `push`、`pop` 等函数包起来，对外只提供简单接口（如栈和队列的实现）。
*   **布尔逻辑**：利用真/假（1/0）控制程序流程。
*   **递归**：函数自己调用自己。必须有 Base Case（终止条件）和递推关系（如归并排序、倒序打印）。
*   **迭代与增量式求解**：循环就是迭代；插入排序就是每次加入一个新元素，保持当前子数组有序。
*   **函数式编程**：尽量减少全局状态，把函数当做黑盒，输入参数决定输出结果。
*   **抽象**：用 `struct` 隐藏数据的内部细节，只用名字去访问。
*   **数据驱动**：用查表法（如多维数组存星期字符串）代替冗长的 `if/else` 或 `switch`。
*   **分而治之**：把大问题拆成小问题（如归并排序）。
*   **折半查找**：每次砍掉一半搜索空间，时间从 \(O(n)\) 降到 \(O(\log n)\)。
*   **回溯**：在 DFS 迷宫算法中，走到死胡同后退回上一步，换条路继续走。

# 3 调试方法

*   **错误的分类**：
    *   **编译错误**：语法写错（如漏了分号），编译器直接报错，无法生成可执行文件。
    *   **运行时错误**：如段错误（数组越界、空指针解引用），程序在运行中崩溃。
    *   **语义错误（逻辑错误）**：程序不崩溃，但结果不对（如 `sum` 忘记初始化，死循环）。
*   **增量式开发**：不要一次性写几百行，写一个函数测一个函数。
*   **打印语句与 Scaffold**：在没有调试器的环境下，用 `printf` 打印中间变量是最朴素有效的办法。调试完后记得删掉或注释掉。
*   **GDB**：强大的命令行调试器。
    *   `b` (break)：打断点。
    *   `r` (run)：运行。
    *   `n` / `s`：单步执行。
    *   `p` (print) / `display`：查看变量。
    *   `bt`：查看函数调用栈。
*   **DbC (契约式设计) 与 Assertion (断言)**：
    *   函数作者和调用者之间订立契约（Precondition 前置条件，Postcondition 后置条件）。
    *   用 `assert()` 在代码里严格检查这些条件，如果违背就立刻中止程序。这有助于在开发阶段快速定位 Bug。
